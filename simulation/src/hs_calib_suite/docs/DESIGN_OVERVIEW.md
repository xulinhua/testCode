# HS Calib Suite — 整体设计方案

> 版本：2026-08-20（修订：调试三模式）  
> 范围：`simulation/src/hs_calib_suite`  
> 目的：厘清「工程标定」与「检测调试」产品边界；调试侧明确三种能力，并给出 UI / 架构 / 分块落地方案。

---

## 0. 一句话定位

**HS Calib Suite** 是面向机器人现场的 **标定工作台**：正式路径产出可用标定结果；调试路径帮助现场快速确认「看得见板、认得出类型、参数设得对」。算法在 `core/`（无 ROS），GUI 只做编排与可视化。

---

## 1. 现状问题（为何要整理）

| 问题 | 表现 |
|------|------|
| **任务类型混杂** | 首页把正式标定器与检测调试并列，易误进无采集的调试页 |
| **调试能力不全** | 现有仅「局部检出 / 完整板验收」，缺少「这是什么板」的类型识别 |
| **双轨 UI** | 正式 5 步 vs 检测台旁路；步骤条在检测台失效 |
| **参数入口分裂** | Setup 与检测台两套板参表单，单位/默认值不完全一致 |
| **模式映射隐式** | 检测台内部映射求解器 ID，转入工作台时静默切换 |

本方案以 **工程标定 / 检测调试 分离** 为纲，并把调试拆成 **三个互不混淆的子模式**。

## 2. 产品信息架构

### 2.1 两大产品线

```
┌─────────────────────────────────────────────────────────────────┐
│                        HS Calib Suite                            │
├──────────────────────────────┬──────────────────────────────────┤
│  A. 工程标定（Calibration）   │  B. 检测调试（Detect Lab）         │
│  目标：产出标定结果文件        │  目标：现场验板 / 调参 / 认类型    │
│  出口：YAML / 结果包           │  出口：叠加图 · 类型结论 · 可选草稿│
│  流程：5 步向导                │  流程：数据源 → 调试台（按模式变参）│
└──────────────────────────────┴──────────────────────────────────┘
```

**原则**

1. 首页先选 **工程标定 / 检测调试**，再选具体任务。
2. 调试台可「采集草稿 / 转入工程标定」，但不得冒充完整标定向导。
3. 工程标定必须：数据源 → 标定设置 → 工作台 → 复核。
4. 首页布局：**工程标定 = 左侧分类 + 密列表（方案 A）**；**检测调试 = 三卡等分画廊（方案 B）**。

### 2.2 正式标定：任务矩阵

| 分类 | 任务 ID | 名称 | 状态 | 典型输出 |
|------|---------|------|------|----------|
| 内参 | `cam_intrinsics` | 单目内参 | ✅ | `camera_intrinsics.yaml` |
| 内参 | `stereo_intrinsics` | 双目各自内参 | ✅ | `camera_left/right.yaml` |
| 内参 | `trihedral_oneshot` | 直角三面内参 | ✅ | 内参 YAML |
| 手眼 | `eye_in_hand` | 眼在手上 | ✅ | `handeye_extrinsics.yaml` |
| 手眼 | `eye_to_hand` | 眼在手外 | ✅ | `handeye_extrinsics.yaml` |
| 外参 | `stereo_extrinsics` | 双目相对外参 | ✅ | `stereo_extrinsics.yaml` |

### 2.3 检测调试：三种模式（核心修订）

调试不是「一种页面两种文案」，而是 **三种明确任务**：

| 任务 ID | 名称 | 一句话目标 | 是否要板尺寸 | 是否要指定类型 | 状态 |
|---------|------|------------|--------------|----------------|------|
| `detect_lab_identify` | **标定板类型识别** | 只回答「当前是什么板」 | ❌ 不管 | ❌ 自动试探 | ✅ 已落地 |
| `detect_lab` | **局部特征检测** | 已知类型下，残缺也尽量检出 | ✅ 需要（或默认值） | ✅ 用户指定 | ✅ 已有 |
| `detect_lab_full` | **完整板检测** | 已知类型下，只认整面及格 | ✅ 需要 | ✅ 用户指定 | ✅ 已有 |

> 三者都 **不是** `CalibratorRegistry` 求解器；仅调试策略 / UI 模式。

#### 2.3.1 模式对比（怎么选）

```
现场拿到一块板 / 一帧图
        │
        ▼
  不知道是什么板？ ──是──► 【类型识别】detect_lab_identify
        │否
        ▼
  已知类型，要调检测能力 / 看残缺能否检出？
        │
        ├─ 要「尽量检出」──► 【局部特征】detect_lab
        └─ 要「采集验收、残缺直接失败」──► 【完整板】detect_lab_full
```

| 维度 | 类型识别 | 局部特征 | 完整板 |
|------|----------|----------|--------|
| 用户要填的 | 几乎无（可选字典提示） | 类型 + 网格 + 尺寸等 | 同左 |
| 算法行为 | 多类型试探 / 投票，出候选列表 | 单类型 + partial | 单类型 + full |
| 尺寸 | **忽略几何尺度**（可用占位边长） | 参与物点/置信度 | 同左 |
| 主按钮 | 「识别类型」 | Thorough / Fast | 完整检测 / 快速完整 |
| 结果展示 | Top-K 类型 + 置信度 + 简图叠加 | 角点/码叠加 + 点数 | 成功/失败 + 叠加 |
| 转入标定 | 可一键带入「识别出的类型」到 Setup | 可带入当前板参 | 同左 |

#### 2.3.2 类型识别模式 — 功能设计

**目标**：只检测 / 判断 **当前画面里标定板的类型**，**不关心、不要求** 真实物理尺寸。

**建议输出（UI）**

```
识别结果
├─ 最可能：charuco          score 0.86
├─ 其次：  chessboard       score 0.41
├─ 再次：  aruco_grid       score 0.22
└─ 附带提示：建议字典 DICT_4X4_50（若选 ChArUco）
```

**实现要点（core）**

1. 新增调试用管线（建议名）：`BoardTypeIdentifier`（可放 `core/detectors/` 或 `core/tools/`）。
2. 对候选类型集合依次做 **轻量探测**（Fast 路径），例如：
   - `chessboard`：经典找角 / SB，不依赖真实方格边长（边长用占位 `1.0` 仅建板）。
   - `circles_*`：找圆心阵列，同样占位间距。
   - `aruco` / `aruco_grid` / `charuco` / `aprilgrid`：按常见字典列表短扫（可配置），以「检出码数 / 角点数」打分。
   - `trihedral_*`：若多面聚类命中再加分（可选，P1）。
3. **尺寸字段在 UI 隐藏或禁用**；内部一律占位，避免误导用户去量板。
4. 打分建议：`检出特征数`、`分布面积比`、`是否像规则网格` 加权；输出归一化 score。
5. 可视化：对 Top-1（或用户点选的候选）画叠加；不必生成正式 Observation 物点尺度。

**不做的事**

- 不求解内参/外参。
- 不要求 `square_length` / `marker_length` 正确。
- 默认不自动「采集帧」（可选手动保存识别截图）。

#### 2.3.3 局部 / 完整模式（已有，口径收紧）

| | `detect_lab` | `detect_lab_full` |
|--|--------------|-------------------|
| `detect_completeness` | `partial` | `full` |
| 典型用途 | 调试检测器、残缺视野 | 采集前验收「这一帧能不能用」 |
| 板参 | **需要**：类型、网格；尺寸建议填对（影响置信度/物点） | 同左 |
| 会话映射 | 检测时借用 `cam_intrinsics` 或 `trihedral_oneshot` 路由 | 同左 |

### 2.4 靶标类型一览（正式标定 + 识别候选）

| 靶标 ID | 说明 | 正式标定 | 类型识别候选 |
|---------|------|----------|--------------|
| `chessboard` | 棋盘内角点 | ✅ | ✅ 默认开 |
| `charuco` | ChArUco | ✅ | ✅ 默认开 |
| `aruco` / `aruco_grid` | 单码 / 码阵 | ✅ | ✅ 默认开 |
| `aprilgrid` | Kalibr Aprilgrid | ✅ | ✅ 默认开 |
| `circles_symmetric` / `asymmetric` | 圆点阵 | ✅ | ✅ 默认开 |
| `trihedral_chess` / `charuco` / `aruco` | 直角三面 | ✅ | ⭕ 可选（较重） |

## 3. UI 流程与简图

### 3.1 正式标定五步

```
┌──────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 1 任务│──►│ 2 数据源 │──►│ 3 标定设置│──►│ 4 采集求解│──►│ 5 复核导出│
└──────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

步骤条 **只服务正式标定**。

### 3.2 检测调试路径

```
┌──────┐   ┌──────────┐   ┌─────────────────────────────────────┐
│ 1 任务│──►│ 2 数据源 │──►│ 调试台（同一 PageId::DetectLab）      │
└──────┘   └──────────┘   │  按子模式切换右侧参数与主按钮         │
  三选一：                  └──────────────┬──────────────────────┘
  identify / lab / full                    │
                                           ├─ 识别 / Thorough / 完整检测
                                           ├─ （局部·完整）采集帧
                                           └─ 转入正式标定 → Setup/Workbench
```

### 3.3 首页简图

```
┌─ 菜单 ────────────────────────────────── [就绪] [离线] [在线] ─┐
├─ ( ● 工程标定 )  ( ○ 检测调试 ) ────────────────────────────────┤
├──────────────┬──────────────────────────────────────────────────┤
│ 项目工作区    │ 【正式】内参|手眼|外参|多传感器 磁贴               │
│              │ 【调试】三张磁贴：                                  │
│              │   ┌类型识别┐ ┌局部特征┐ ┌完整板检测┐              │
│              │   └────────┘ └────────┘ └──────────┘              │
│              │                            [下一步：数据源 →]     │
└──────────────┴──────────────────────────────────────────────────┘
```

### 3.4 调试台 — 按模式变体

#### （1）类型识别 `detect_lab_identify`

```
┌─ 检测预览 ──────────────┬─ 识别设置（极少）─────────────────────┐
│ 实时/离线画面            │ 可选：字典提示（多选常见 DICT）         │
│ + Top-1 类型叠加         │ 可选：候选类型勾选（默认全开平面靶）   │
│                          │ ❌ 无 squares / 尺寸 输入               │
│                          ├─ 动作 ───────────────────────────────┤
│                          │ [识别类型]  [应用类型到正式标定 →]     │
│                          ├─ 结果 ───────────────────────────────┤
│                          │ 1. charuco     0.86                   │
│                          │ 2. chessboard  0.41                   │
│                          │ 3. …                                  │
└──────────────────────────┴───────────────────────────────────────┘
```

#### （2）局部特征 `detect_lab` / （3）完整板 `detect_lab_full`

```
┌─ 检测预览 ──────────────┬─ 靶标参数（类型+网格+尺寸 mm）────────┐
│ 叠加检出                 │ 图像源快捷 · 上一张/下一张             │
│                          ├─ 动作（底部固定）────────────────────┤
│                          │ [Thorough|完整检测][Fast][采集帧]      │
│                          │ [转入正式标定工作台 →]                 │
└──────────────────────────┴───────────────────────────────────────┘
```

完整模式与局部模式 **同一布局**，差异在标题、主按钮文案、`detect_completeness`。

### 3.5 数据源 / 标定设置 / 工作台 / 复核

与前版一致，要点：

- **数据源**：调试模式隐藏内参源/TF 等与求解无关块。
- **标定设置**：仅正式标定；尺寸 UI 用 mm。
- **工作台**：实时静默检测；冻结停异步链；按钮定宽。
- **复核**：残差图 / 覆盖图可缩放放大。

## 4. 设计架构

```
                    ┌─────────────────────────────┐
                    │   GUI  Shell (MainWindow)     │
                    └──────────────┬──────────────┘
           ┌───────────────────────┼───────────────────────┐
           ▼                       ▼                       ▼
   ┌───────────────┐     ┌─────────────────┐     ┌─────────────────┐
   │ Config Panels │     │ SessionController│     │ Bridges          │
   └───────────────┘     │ + LabMode 枚举    │     └─────────────────┘
                         └────────┬────────┘
                                  ▼
                         ┌─────────────────┐
                         │ core/            │
                         │ Detector(s)      │
                         │ BoardTypeIdentifier │  ← 新增（类型识别）
                         │ Calibrator       │
                         └─────────────────┘
```

### 4.1 调试模式枚举（建议）

```text
enum class DetectLabMode {
  Identify,   // detect_lab_identify — 类型识别，忽略尺寸
  Partial,    // detect_lab         — 局部特征
  Full,       // detect_lab_full    — 完整板
};
```

首页磁贴 ID 与枚举一一对应；`PageId::DetectLab` 共用一页，用 `DetectLabMode` 切换 UI/管线。

### 4.2 类型识别数据流

```
ImageFrame
    │
    ▼
BoardTypeIdentifier::run(candidates, dict_hints)
    │  对每个候选：占位几何 → Detector(fast) → FeatureScore
    ▼
vector<TypeHypothesis{ id, score, overlay_hint, dict_hint }>
    │
    ▼
GUI：列表 + Top-1 叠加；「应用类型」写入正式标定 BoardParams.target
```

### 4.3 异步检测管线（局部/完整继续沿用）

```
request_detect(fast) → worker → detect_finished
冻结/求解/离页：cancel_pending_detect()
```

类型识别建议 **独立入口** `request_identify()`（可同步或异步），避免与正式 `request_detect` 的 `pending` 链搅在一起。

## 8. UI 归类原则

1. **调试三模式名称见名知意**：识别 / 局部 / 完整，禁止再用含糊的「检测台」统称主按钮。
2. **类型识别页禁止尺寸控件**，避免用户以为「尺寸不准所以识别失败」。
3. 局部/完整才显示网格与尺寸；转入正式标定时带上当前（或识别出的）类型。
4. 操作区定宽、路径省略、异步可预期、就绪图标化——与正式路径一致。

## 10. 成功标准

1. ✅ 用户能分清：正式标定 vs 三种调试。
2. ✅ **类型识别**：不填尺寸也能给出可信 Top-K；页面上没有尺寸输入。
3. ✅ 局部/完整：参数齐全；完整模式残缺必失败。
4. ✅ 识别结果可一键带到正式标定设置。
5. ✅ ROS 在线时三种调试都能看到实时图。
